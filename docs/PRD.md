# PRD - MindFlow v1.1

## 1. 产品概述

### 一句话描述
MindFlow 是一个融合思维导图与任务管理的网页版个人项目推进工具——在多个项目的思维导图中直接拆解任务、设置截止日期、追踪进度，并通过全局任务看板跨项目聚合管理，让"想清楚"和"做下去"在多项目间无缝衔接。

### 目标用户
- **主要用户**：25-35 岁知识工作者（产品经理、设计师、开发者、自媒体创作者），需要同时管理多个创意构思和落地执行项目
- **次要用户**：大学生/研究生，用于论文规划、复习计划、社团项目等多线并行管理
- **技术水平**：中等（能使用网页工具，不需要技术背景）

### 核心价值主张
**"从发散到收敛，多个项目一张图管到底"**
- 思维导图负责"想清楚"——每个项目独立拆解、梳理逻辑、发散创意
- 任务管理负责"做下去"——设置截止、追踪进度、按时交付
- 全局看板负责"看得全"——跨项目聚合所有任务，一眼看清今日/本周要做什么
- 切换成本趋近于零——在导图、项目看板、全局看板三种视图间无缝切换

### 竞品差评提炼的关键市场空白
1. **思维导图工具的任务管理是"假任务管理"**——Xmind直到2025年才加入任务字段（优先级/分工/进度/时间），且仅Pro+可用，无法设置提醒、无看板视图、无日历视图
2. **任务管理工具的可视化是"假可视化"**——滴答清单的列表/日历视图无法展示复杂项目的层级依赖关系，项目一复杂就失控
3. **Notion/Obsidian能做但太慢太复杂**——Notion每次打开要加载、搜索卡顿；Obsidian需要配十几个插件才能勉强实现，不适合非技术用户
4. **"想清楚"和"做下去"之间存在断裂**——用户需要在 Xmind 里拆解，再手动搬运到滴答清单里执行，两边信息不同步，改一边另一边就过时
5. **缺乏跨项目的全局视角**——滴答清单有全局任务列表但无层级结构；Xmind 每个文件是独立导图，跨项目看全局进度非常困难

## 3. 我们的差异化定位

用户为什么选 MindFlow 而不是 Xmind+滴答清单？

| 场景 | 用 Xmind + 滴答清单 | 用 MindFlow |
|------|---------------------|-------------|
| 项目拆解 | 在 Xmind 画导图 → 手动复制到滴答清单 | 导图节点一键标记为任务，自动同步到项目看板 |
| 多项目管理 | Xmind 每个文件独立，滴答清单靠标签/文件夹勉强分类，跨项目进度无法一眼看清 | 侧边栏项目列表 + 全局任务看板，所有项目的进度和截止日一目了然 |
| 需求变更 | Xmind 改了结构 → 再到滴答清单改一遍 | 改导图自动更新任务层级和依赖 |
| 进度查看 | 打开滴答清单看列表/日历 | 在导图上直接看每个节点的完成进度（颜色/进度条） |
| 截止提醒 | 滴答清单弹通知 | 思维导图节点高亮提醒，不跳出当前上下文 |
| 全局任务 | 滴答清单的全局列表是扁平的，看不到任务在项目中的层级位置 | 全局看板按项目分色分组，点击任务卡片可直接跳转到对应项目的思维导图节点 |
| 导出交付 | Xmind 导出 PNG/PDF，滴答清单导出 CSV，两份文件 | 一份文件同时包含结构图+任务表，统一导出 |

**核心差异化**：我们不是"思维导图里加一点任务标记"，也不是"任务工具里加一个树状视图"，而是**让思维导图的节点和任务系统中的任务对象是同一个实体**——在导图里改结构，任务视图自动变；在任务视图改状态，导图节点自动更新；在全局看板管理跨项目任务，改状态同步回对应项目的思维导图。

## 4. 用户画像与场景

### 用户画像 1：小林，27 岁产品经理
- **场景**：同时负责三个并行项目——"首页改版"、"搜索优化"、"会员体系"
- **现在的痛苦**：三个项目各有一份 Xmind 导图和一份滴答清单，每天早上要在多个文件和列表间切换确认进度；滴答清单的全局视图看不到每个任务属于哪个项目、在项目中的层级位置
- **MindFlow 的价值**：三个项目各在一个思维导图中拆解，全局看板一眼看清所有待办任务的跨项目分布，点击任务直接定位到对应项目的导图节点

### 用户画像 2：阿杰，30 岁独立开发者
- **场景**：同时推进主业项目、Side Project、技术博客三个方向
- **现在的痛苦**：用 Notion 管理项目，但 Notion 没有思维导图，复杂功能的依赖关系看不清楚；用回 Xmind 又无法追踪跨项目的整体进度
- **MindFlow 的价值**：每个方向一个思维导图项目，全局看板按项目分色显示，防止某个方向被遗忘，同时每个项目内部用导图看清依赖关系

### 用户画像 3：小雨，24 岁研究生
- **场景**：毕业论文撰写 + 实验安排 + 导师项目 + 社团活动，多线并行
- **现在的痛苦**：用幕布做大纲转导图，但只能管一个文档；用滴答清单设了 deadline 看不到各任务在不同项目中的逻辑关系
- **MindFlow 的价值**：论文/实验/导师/社团各为一个项目，全局看板按截止日期聚合提醒，防止漏掉任何一个方向的 deadline

### RICE 评分说明
- **Reach**：目标用户中有多少比例会使用该功能（%）
- **Impact**：对用户体验的影响程度（1-10）
- **Confidence**：对估算的确信程度（%）
- **Effort**：开发成本（XS=1, S=2, M=3, L=5, XL=8）
- **Score = (Reach × Impact × Confidence) / Effort**

### MVP 范围（v1.1）
保留 **RICE 评分最高且相互依赖的核心功能**：
1. **思维导图编辑** + **本地数据持久化**（基础载体 + 数据存储）
2. **节点转任务**（核心价值——打通"想清楚"和"做下去"）
3. **看板视图** + **双向同步**（任务落地的核心交互——从图到执行的切换）
4. **项目管理**（多项目的基础设施——创建/切换/删除/侧边栏导航）
5. **全局任务管理**（跨项目聚合——一键看清所有待办，按项目/优先级筛选，全局看板分色分组）

其余全部进 Backlog。

## 6. 核心用户旅程

### 旅程 1：从零创建项目 → 思维导图拆解 → 任务化 → 看板追踪

**步骤 1：创建项目**
- 用户进入 MindFlow，侧边栏显示"+ 新建项目"按钮
- 点击后弹窗输入项目名称，选择思维导图结构模板（默认逻辑图）
- 新创建的"Q3 产品改版"项目出现在侧边栏列表中，自动进入该项目

**步骤 2：思维导图拆解**
- 用户在中心主题下添加分支：需求分析 → 视觉设计 → 前端开发 → 测试上线
- 继续向下拆解：前端开发 → 首页重构 → 组件库搭建 → 响应式适配
- 使用 Tab/Enter 快速创建子节点/兄弟节点，拖拽调整层级

**步骤 3：节点任务化**
- 用户选中"首页重构"节点，点击"转为任务"
- 节点右侧出现：复选框 ☐、截止日期选择器（设为 7 月 15 日）、优先级标签（P1 高优）
- 同时，该节点自动出现在该项目"任务看板"的"To Do"列中

**步骤 4：看板追踪**
- 用户点击主界面顶部的"看板"标签切换到看板视图
- 看到"首页重构"卡片在 To Do 列
- 开始开发后，拖拽卡片到"In Progress"
- 开发完成后，拖拽到"Done"，回到思维导图发现该节点已自动显示为完成状态（灰色+打勾）

**步骤 5：需求变更**
- 产品插入新需求"深色模式适配"
- 用户在思维导图中"前端开发"下新增节点并转为任务
- 项目看板中自动出现新卡片，无需手动同步

### 旅程 2：管理多个项目 → 全局任务看板 → 跨项目追踪

**步骤 1：创建第二个项目**
- 用户在侧边栏点击"+ 新建项目"，输入"技术博客改版"
- 侧边栏现在显示两个项目："Q3 产品改版"和"技术博客改版"
- 用户点击可自由切换，每个项目保持独立的思维导图和看板

**步骤 2：在第二个项目中拆解任务**
- 用户在"技术博客改版"中建立思维导图：主题设计 → 文章迁移 → SEO 优化 → CDN 加速
- 将"文章迁移"和"SEO 优化"转为任务并设置截止日期

**步骤 3：查看全局任务**
- 用户点击侧边栏底部的"全局任务"入口
- 主界面切换为全局任务列表，显示所有项目中已标记为任务的节点
- 列表按项目分组，每个任务显示：所属项目名称（带颜色标签）+ 任务名称 + 截止日期 + 优先级 + 状态

**步骤 4：全局看板筛选**
- 用户点击"看板视图"，全局看板显示所有项目的任务卡片
- 顶部筛选栏选择：项目 = "全部"，优先级 = "P1 高优"
- 看板只显示所有项目中的高优先级任务
- 任务卡片的颜色边框标识其所属项目（项目 A 蓝色、项目 B 绿色等）

**步骤 5：在全局看板推进任务**
- 用户在全局看板看到"首页重构"（来自 Q3 产品改版）
- 将该卡片从"To Do"拖拽到"In Progress"
- 状态变更自动同步回"Q3 产品改版"项目的思维导图和项目看板

**步骤 6：从全局任务定位到项目导图**
- 用户在全局任务列表中点击"SEO 优化"任务
- 自动切换到"技术博客改版"项目的思维导图视图，并高亮定位到"SEO 优化"节点
- 用户可立即在导图的上下文中理解这个任务在项目中的位置和依赖关系

### 旅程 3：大纲速记 → 一键转导图 → 任务批量化

**步骤 1：大纲速记**
- 用户切换"大纲模式"，快速键入：
  ```
  Q3 产品改版
    需求分析
      用户调研报告（截止7.1，高优）
      竞品分析（截止7.3）
    视觉设计
      首页 mockup（截止7.8，高优）
  ```

**步骤 2：一键转导图**
- 点击"转为思维导图"，文本层级自动映射为导图结构
- 括号内的截止和优先级自动解析为任务字段

**步骤 3：批量任务化**
- 选中多个节点，点击"全部转为任务"
- 所有带截止日期的节点自动出现在看板中

## 8. 验收标准（Given/When/Then）

### 用户旅程 1 验收标准

**AC-1：创建节点**
- Given 用户在思维导图画布上，When 按 Enter 键 / 点击"添加节点"按钮，Then 在当前节点旁创建一个同级兄弟节点，光标自动进入编辑态

**AC-2：节点任务化**
- Given 用户选中一个普通节点，When 点击"转为任务"按钮，Then 该节点左侧出现复选框，右侧出现截止日期和优先级字段，同时该任务在项目看板"To Do"列中出现

**AC-3：拖拽改状态**
- Given 用户在看板视图的"To Do"列中看到一个任务卡片，When 将该卡片拖拽到"Done"列，Then 卡片移动到"Done"列，同时思维导图中对应节点显示为完成状态（灰色+打勾）

**AC-4：双向同步**
- Given 用户在思维导图中将一个已完成任务的复选框取消勾选，When 操作完成后，Then 项目看板中该卡片自动从"Done"列移回"To Do"列

**AC-5：数据持久化**
- Given 用户已创建包含多个节点和任务的思维导图项目，When 刷新浏览器页面，Then 页面加载完成后，思维导图和看板状态与刷新前完全一致

### 用户旅程 2 验收标准（多项目 + 全局任务）

**AC-6：创建项目**
- Given 用户在 MindFlow 侧边栏，When 点击"+ 新建项目"并输入名称"项目A"，Then 侧边栏出现"项目A"，主画布切换到空白思维导图，该项目有独立的导图和看板数据空间

**AC-7：项目切换**
- Given 用户已创建"项目A"和"项目B"两个项目，When 在侧边栏点击"项目B"，Then 主画布显示项目B的思维导图，顶部显示当前项目名称为"项目B"

**AC-8：项目数据隔离**
- Given 用户在"项目A"的思维导图中创建了节点和任务，When 切换到"项目B"，Then 项目B的画布中没有项目A的任何节点和任务数据

**AC-9：全局任务列表聚合**
- Given 用户已有"项目A"（包含2个任务）和"项目B"（包含3个任务），When 点击侧边栏"全局任务"，Then 主界面显示包含5个任务的列表，每个任务显示所属项目名称和颜色标签

**AC-10：全局任务筛选**
- Given 用户处于全局任务视图，When 在筛选栏选择"项目 = 项目A"，Then 列表只显示项目A的2个任务，项目B的任务被隐藏

**AC-11：全局看板分色**
- Given 用户处于全局看板视图且有两个项目（项目A 蓝色、项目B 绿色），When 查看看板列中的任务卡片，Then 项目A的卡片显示蓝色边框/标签，项目B的卡片显示绿色边框/标签

**AC-12：全局→项目双向同步**
- Given 用户在全局看板中将"项目A"的某个任务卡片从"To Do"拖拽到"Done"，When 操作完成后，Then 切换到"项目A"的思维导图，该任务对应节点显示为完成状态；切换到"项目A"的项目看板，该卡片位于"Done"列

**AC-13：全局任务定位到项目导图**
- Given 用户在全局任务列表中点击某个任务名称，When 点击后，Then 界面自动切换到该任务所属项目的思维导图视图，该节点被高亮选中并滚动到可视区域中央

### 边界条件

**空状态**
- 新用户首次进入，侧边栏为空，主画布显示"创建你的第一个项目"引导按钮
- 项目内画布为空时，显示引导提示"按 Enter 创建第一个节点"
- 项目看板视图无任务时，显示"还没有任务，在思维导图中将节点转为任务即可开始追踪"
- 全局任务视图无任务时，显示"还没有任务，在各项目的思维导图中将节点转为任务即可全局追踪"

**错误状态**
- 本地存储空间满时，提示"存储空间不足，请导出数据或清理旧项目"
- 节点内容过长（>500 字）时，显示省略号并提供展开按钮
- 删除项目时弹窗二次确认，删除操作不可逆，提示"此操作将删除该项目及所有数据"

**加载状态**
- 导图节点超过 200 个时，显示骨架屏/进度条
- 首次加载 IndexedDB 数据时，显示"正在恢复您的项目..."
- 切换项目时，若数据量大，显示项目切换进度指示

**边界值**
- 支持最多 20 个项目
- 支持最多 10 层嵌套层级
- 单个项目最多 1000 个节点
- 节点文本长度限制 2000 字符

## 10. 风险提示

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| wanglin2/mind-map 库的扩展性不足 | 高 | 早期验证节点任务化是否能在该库上实现，若不行提前换方案 |
| "思维导图+任务管理"的需求伪命题 | 高 | MVP 不做登录，用本地存储快速上线验证用户留存 |
| MVP 功能太单薄无法吸引用户 | 中 | 明确对标"比你用 Xmind+滴答清单更高效"，而非替代两者全部功能 |
| 移动端体验差 | 中 | MVP 明确仅支持桌面端，移动端放远期 |
| IndexedDB 存储容量限制（~50MB） | 中 | 监控存储用量，超限提示导出清理；云端同步后此问题缓解 |
| 多项目数据模型设计不当导致后续扩展困难 | 高 | architect 阶段必须评审项目+节点+任务的数据关系设计 |
