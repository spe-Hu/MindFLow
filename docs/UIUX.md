## 1. 设计方向

### 1.1 对标品牌

| 品牌 | 对标维度 | 借鉴点 |
|------|---------|--------|
| **Linear** | 全局框架、暗黑主题、交互精度 | 倒 L 形全局导航框架、极简 Token 体系、列表行 hover 操作、Command 面板体验 |
| **Notion** | 侧边栏导航、页面组织 | 可折叠侧边栏、页面树结构、简洁的页面切换、项目/页面层级组织 |
| **Xmind** | 思维导图节点样式、分支配色 | 层级递减的视觉权重、分支异色系统、节点形状语义、清晰的连线层级 |
| **滴答清单 (TickTick)** | 任务信息密度、优先级标识 | 任务卡片信息排列、标签/tag 系统、完成态视觉、截止日期标识、全局列表聚合 |

### 1.2 设计语言关键词

- **克制 (Restrained)** — 色彩用量极低，90% 界面由中性色构成，仅在节点、优先级、项目标识、交互反馈处出跳
- **层级 (Hierarchical)** — 信息通过字号、字重、透明度、空间三层建立清晰层级，不做无意义装饰
- **精准 (Precise)** — 所有元素对齐到 4px 网格，hover/active/focus 状态在 150ms 内完成过渡
- **沉浸 (Immersive)** — 思维导图区域最大化内容空间，UI chrome 尽可能收缩存在感
- **清晰 (Lucid)** — 普通节点与任务节点的区分在一瞥之间即可辨认；跨项目任务通过颜色+项目名称双重编码即刻识别来源

### 1.3 设计语言定位

MindFlow 的定位是 **"工具型产品的视觉进化"** — 不追求第一眼惊艳，追求第 100 次使用时的依然舒适。核心用户场景是：**高频、长时间、专注态**的多项目规划与推进。设计以"降低认知负荷"为第一优先，美学服务于效率。

**v1.1 新增定位**：从"单项目思维导图+任务"升级为"多项目工作台"——侧边栏成为项目的"停泊港"，全局任务成为跨项目作业的"指挥中心"。

### 2.4 任务优先级色

优先级色在 MindFlow 中承担高语义权重，必须在所有视图（思维导图、列表、看板、全局任务）中保持一致。

| 优先级 | Token | 色值 | 视觉形态 |
|--------|-------|------|---------|
| 高 (High) | `--priority-high` | `#EF4444` (danger-500) | 实心圆点 `#EF4444` + 任务节点/卡片左侧 3px 红色竖条标识 |
| 中 (Medium) | `--priority-medium` | `#F59E0B` (warning-500) | 实心圆点 `#F59E0B` + 任务节点/卡片左侧 3px 橙色竖条标识 |
| 低 (Low) | `--priority-low` | `#3B82F6` (info-500) | 空心圆点 `#3B82F6` + 任务节点/卡片左侧 3px 蓝色竖条标识 |
| 无 (None) | `--priority-none` | `#94A3B8` (slate-400) | 无圆点，无边框标识 |

> **规则**：列表/看板视图中的任务卡片，优先级通过左侧竖条 + 圆点共同标识；思维导图视图中的任务节点，通过节点形状差异 + 左侧竖条 + 圆点共同标识。双重编码确保色盲用户也能区分。

### 2.5 项目颜色标识系统（v1.1 新增）

每个项目分配一个项目色，用于在全局视图中一眼识别任务归属。项目色与思维导图分支色彩系统共用同一套 6 色池，形成"项目-分支-全局"三端一致的色彩体验。

| 项目色编号 | Token | 色值 | 用途 |
|-----------|-------|------|------|
| Project-1 | `--project-indigo` | `#4F46E5` | 默认项目色，对应 Indigo 分支 |
| Project-2 | `--project-teal` | `#0D9488` | 对应 Teal 分支 |
| Project-3 | `--project-amber` | `#D97706` | 对应 Amber 分支 |
| Project-4 | `--project-rose` | `#BE123C` | 对应 Rose 分支 |
| Project-5 | `--project-emerald` | `#059669` | 对应 Emerald 分支 |
| Project-6 | `--project-violet` | `#7C3AED` | 对应 Violet 分支 |

#### 项目色在 UI 中的呈现位置

| 位置 | 呈现形态 | 尺寸 |
|------|---------|------|
| Sidebar 项目列表 | 10px 实心圆点，位于项目名称左侧 | 10px |
| 全局任务列表行 | 10px 实心圆点 + 项目名称缩写标签 | 10px + 标签 |
| 全局看板卡片 | 卡片顶部 3px 横条 + 卡片边框变为项目色 1.5px | 3px 横条 |
| 项目名称标签（Tag） | `radius-full` 胶囊形状，背景为项目色 10% opacity，文字为项目色深 1 级 | 胶囊 |

> **关键原则**：项目色**绝不**与优先级色出现在同一空间位置。项目色位于元素的最外缘（列表行左边缘 / 卡片顶部），优先级色位于元素的内侧（标题旁 / 卡片左边缘竖条）。两者在 UI 空间中保持至少 8px 的物理距离，确保用户不会混淆"这是哪个项目的任务"和"这个任务有多紧急"。

### 2.6 思维导图节点颜色体系

MindFlow 的思维导图颜色体系需要在以下维度做出权衡：
- **层级识别**：不同层级节点必须有清晰的视觉区分
- **任务标记**：任务节点必须在一瞥之间被识别
- **分支区分**：不同一级分支可使用不同颜色增强空间识别
- **项目关联**：项目的分支色可与项目标识色关联（可选）
- **克制使用**：不以多彩为目标，以清晰为目标

#### 2.6.1 默认节点配色（不以分支颜色区分时）

| 节点层级 | 填充色 | 边框色 | 文字色 | 连线色 | 形状 |
|---------|--------|--------|--------|--------|------|
| 根节点 (Root) | `--bg-surface` | `--color-primary` 2px | `--text-primary` | `--color-primary` | 圆角矩形 (`radius-lg`) |
| 二级节点 (L1) | `--bg-surface` | `--border-default` 1px | `--text-primary` | `--text-muted` | 圆角矩形 (`radius-md`) |
| 三级+节点 (L2+) | `transparent` | `transparent` | `--text-secondary` | `--text-muted` | 无形状（纯文本节点） |
| **任务节点（任意层级）** | `--bg-surface` | `--border-default` 1px + 优先级色左侧竖条 | `--text-primary` | 继承父级 | 圆角矩形 (`radius-md`) + 复选框 |

#### 2.6.2 分支色彩系统（多分支区分时）

当用户启用"分支着色"时，每个一级分支（根节点的直接子节点）及其所有后代节点继承该分支的配色。配色池固定为 6 色（与项目色池共用）：

| 分支编号 | 主色 | 连线/边框 | 文字色 | 适用场景 |
|---------|------|-----------|--------|---------|
| Branch-1 | `#4F46E5` (indigo) | indigo-500 | slate-900/slate-100 | 默认/主要分支 |
| Branch-2 | `#0D9488` (teal) | teal-500 | slate-900/slate-100 | 技术/开发分支 |
| Branch-3 | `#D97706` (amber) | amber-600 | slate-900/slate-100 | 设计/创意分支 |
| Branch-4 | `#BE123C` (rose) | rose-700 | slate-900/slate-100 | 紧急/风险分支 |
| Branch-5 | `#059669` (emerald) | emerald-600 | slate-900/slate-100 | 完成/验收分支 |
| Branch-6 | `#7C3AED` (violet) | violet-600 | slate-900/slate-100 | 拓展/未来分支 |

> **重要**：Branch-6 使用 `#7C3AED` 仅作为分支/项目标识色之一，用于区分不同语义。这是 **节点/项目级别** 的语义色，不是 UI 渐变或主视觉，不违反"紫色渐变主视觉"红线。

#### 2.6.3 节点连线系统

| 属性 | 值 | 说明 |
|------|-----|------|
| 默认连线样式 | `curve` (贝塞尔曲线) | 仅适用于逻辑结构/思维导图布局 |
| 备选连线样式 | `straight` (直线) | 用于鱼骨图、组织架构等 |
| 连线粗细 | `1.5px`（默认）/ `1px`（三级以下） | 层级递减 |
| 连线颜色 | 继承所属分支色，或 `--text-muted` | 分支着色时跟随分支 |
| 连线圆角 | `radius-sm` (4px) | 直线模式下的转角圆角 |
| 激活连线 | `--color-primary` + 2px 粗细 | 选中节点时其祖先连线高亮 |

## 3. 字体方案

### 3.1 字体栈

```css
:root {
  /* 标题/展示字体：精致、现代、高可读性 */
  --font-display: "Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", -apple-system, BlinkMacSystemFont, sans-serif;

  /* 正文字体：与标题一致，通过字号/字重建立层级 */
  --font-body: "Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", -apple-system, BlinkMacSystemFont, sans-serif;

  /* 等宽字体：用于时间戳、数值、代码片段 */
  --font-mono: "JetBrains Mono", "Fira Code", "SF Mono", monospace;

  /* 思维导图节点字体：确保中英文混排对齐 */
  --font-mindmap: "Noto Sans SC", "Inter", "PingFang SC", -apple-system, sans-serif;
}
```

> **冻结声明**：字体系统已冻结。MindFlow 所有文本渲染使用上述 3 个字体栈，不再引入第四种字体。

### 3.2 字号层级

| Token | 字号 | 字重 | 行高 | 字间距 | 用途 |
|-------|------|------|------|--------|------|
| `text-2xs` | 11px | 400 | 14px | 0 | 时间戳、字数统计、最小标签、筛选器标签 |
| `text-xs` | 12px | 400 | 16px | 0 | 辅助说明、空状态提示、节点展开数、Section 标题 |
| `text-sm` | 13px | 400 | 18px | -0.003em | 侧边栏项目名、标签文字、说明文本、筛选器值 |
| `text-base` | 14px | 400 | 20px | -0.006em | 正文、任务卡片标题、三级+节点、筛选栏文本 |
| `text-md` | 15px | 400 | 22px | -0.009em | 导航栏项目、二级节点文字 |
| `text-lg` | 16px | 500 | 24px | -0.011em | 根节点文字、面板标题、弹窗标题 |
| `text-xl` | 18px | 500 | 26px | -0.014em | Section 标题、侧边栏组标题 |
| `text-2xl` | 20px | 600 | 28px | -0.017em | 页面主标题 |
| `text-3xl` | 24px | 600 | 32px | -0.019em | Hero 标题（仅限 Landing 页，App 内不用） |
| `text-4xl` | 32px | 700 | 38px | -0.021em | 品牌级标题（如空状态插画标题） |

> **规则**：App 内部（工具界面）不使用 24px 以上字号，避免视觉噪音。字号差异通过 `400/500/600` 字重而非单纯放大字号来建立层级。

### 3.3 字体渲染策略

- 全局开启 `-webkit-font-smoothing: antialiased` + `-moz-osx-font-smoothing: grayscale`
- 暗色模式下文本不使用低于 `slate-500` 的颜色，确保对比度 ≥ 4.5:1
- 浅色模式下正文使用 `slate-600` (#475569)，与背景对比度约 7:1
- 所有文本元素支持 `prefers-reduced-motion` 下的无动画切换

## 4. 布局结构

### 4.1 全局布局（倒 L 形框架）

继承 Linear "Inverted L-shape" 全局架构，最大化内容区域。

```
+-------------------------------------------------------------+
|  [Logo]  MindFlow        [全局搜索]      [通知] [头像]       |  ← Header (48px)
+------+------------------------------------------------------+
| 项目A |                                                      |
| 项目B✓|              主内容区域 (思维导图 / 列表 / 看板)        |
| 项目C |                                                      |
| +新建 |                                                      |
|------|                                                      |
|全局任务|                                                      |
|------|                                                      |
| 设置  |                                                      |
+------+------------------------------------------------------+
        ↑
    Resizable (默认 240px, min 180px, max 320px)
```

#### Header（应用头部）
- **高度**：48px（固定）
- **背景**：`--bg-surface`
- **底部边框**：`1px solid --border-default`
- **左侧**：Logo + 全局 Command 搜索框（`Cmd/Ctrl + K` 唤起）
- **中间**：当前上下文指示（项目名称 或 "全局任务"）
- **右侧**：通知铃铛 + 同步状态指示 + 用户头像下拉

> **v1.1 变更**：Header 左侧不再显示"项目名称下拉切换"（v1.0 设计），项目名称移至 Sidebar 项目列表作为选中态展示。Header 中间显示当前上下文的静态指示，作为全局导航的位置锚点。

#### Sidebar（侧边栏）
- **默认宽度**：240px
- **可调整**：支持拖拽调整宽度，最小 180px，最大 320px
- **支持折叠**：点击折叠按钮收为 48px 图标栏（仅图标 + hover 显示 tooltip）
- **背景**：`--bg-surface`（与主区一致，无任何背景色差）
- **内容分区**（v1.1 重新组织）：
  - **项目区（顶部）**：
    - 项目列表：项目色圆点 + 项目名称，最多显示 20 个项目（超出滚动）
    - 每个项目点击切换，当前项目高亮显示
    - Hover 显示操作图标（更多菜单 ×、拖拽手柄 ⋮⋮）
    - 底部 "+ 新建项目" 按钮
  - **分隔线**：`1px solid --border-default`
  - **全局区（中部）**：
    - "全局任务"入口（点击打开全局任务视图）
  - **分隔线**：`1px solid --border-default`
  - **系统区（底部）**：

## 5. 组件规范

### 5.1 思维导图节点

#### 5.1.1 普通节点（非任务）

| 属性 | 根节点 | 二级节点 | 三级+节点 |
|------|--------|---------|----------|
| 背景填充 | `--bg-surface` | `--bg-surface` | `transparent` |
| 边框 | 2px `--color-primary` | 1px `--border-default` | 无 |
| 圆角 | `--radius-lg` (12px) | `--radius-md` (8px) | 无 |
| 内边距 | 12px 20px | 10px 16px | 4px 0px |

| 文字色 | `--text-primary` | `--text-primary` | `--text-secondary` |
| 展开按钮 | 显示在节点右侧/下侧，默认「-」或「+」 | 同左 | 仅当含子节点时显示 |

#### 5.1.2 任务节点（关键差异化设计）

任务节点必须在视觉上有清晰的"这是一个可完成的动作"语义。设计采用 **"卡片化 + 复选框 + 优先级标识"** 的三重编码。

```
+---------------------------------------+
| █ │ [☐]  任务标题文字这里是任务名        |  ← █ = 优先级竖条 (3px)
|   │        红色=高  橙色=中  蓝色=低    |
|   ├── 分割线 ------------------------  |  ← 子任务/备注区域 (可选展开)
|   │ [☐] 子任务 1                       |
|   │ [☑] 子任务 2  (已完成)             |
+---------------------------------------+
```

| 属性 | 值 |
|------|-----|
| 背景填充 | `--bg-surface` |
| 边框 | 1px `--border-default`，hover 时变为 `--border-hover` |
| 优先级竖条 | 节点左侧 3px 实心竖条，颜色 = `--priority-high/medium/low` |
| 圆角 | `--radius-md` (8px) |
| 内边距 | 10px 16px |
| 复选框 | 左侧 16px 方形复选框，未完成 = 空心 1.5px 边框；完成 = 填充 + 白色对勾 |
| 复选框颜色 | 未完成 = `--text-muted`；完成 = `--color-success` (#22C55E) |
| 完成态文字 | 文字添加 `line-through`，颜色变为 `--text-muted` |
| 字号 | `text-base` (14px, 400) |
| 任务元数据行 | 复选框下方，字号 `text-2xs` (11px)，显示截止日期 + 标签 |
| hover 态 | 边框变 `--border-hover`，阴影 `shadow-sm`，出现"更多操作"按钮 |
| 选中态 | `shadow-md` + `--color-primary-ring` 外发光 + 边框变 `--color-primary` |
| focus 态 | `:focus-visible` 显示 `2px` `--color-primary-ring`  outline |

> **关键区分逻辑**：普通节点是"纯信息容器"，无复选框、无优先级竖条、无截止日期；任务节点是"可执行单元"，三者齐全。用户从普通节点"转化"为任务时，节点形状从无边框透明背景变为有边框卡片背景，视觉上产生"实体化"效果。

#### 5.1.3 节点状态对照表

| 状态 | 普通节点表现 | 任务节点表现 |
|------|-------------|-------------|
| Default | 如上述规格 | 如上述规格 |
| Hover | 背景微亮 `--bg-elevated`（三级+节点）/ 边框变 `--border-hover`（有边框节点） | 边框变 `--border-hover`，出现更多菜单图标 |
| Focus | `focus-visible` ring `--color-primary-ring` | 同左 |
| Active | 无特殊变化 | 复选框按下态缩小 0.95 |
| Selected | 连线高亮 + 节点边框变 `--color-primary` | `shadow-md` + 外发光 + 边框变 `--color-primary` |
| Dragging | `opacity: 0.5`，原位置 ghost 占位 | 同左 |
| DropTarget | 下方显示 `2px dashed --color-primary` 插入线 | 同左 |
| Completed | N/A（普通节点无完成态） | 复选框填充绿色 + 文字删除线 + 色调变 muted |

## 6. 交互规范

### 6.1 节点转任务操作流程

这是 MindFlow 最核心的特色交互，必须流畅、直觉、可逆。

#### 6.1.1 正向流程：普通节点 → 任务

**触发方式**：
1. **右键菜单**：右键节点 → "转为任务"（顶部置顶选项）
2. **快捷键**：选中节点后按 `T`
3. **批量转换**：多选节点（Shift/Cmd 多选）后右键 → "转为任务"

**反馈动效**：
- 转换瞬间：节点背景从 `transparent` → `--bg-surface`，边框从 `none` → `1px solid --border-default`，持续 `250ms`，`easing: cubic-bezier(0.4, 0, 0.2, 1)`
- 复选框弹出：从节点左侧滑入，delay 100ms，持续 200ms
- 优先级选择：转换后自动弹出优先级选择浮层（hover 到任一优先级色块即可预览）

**可逆设计**：
- 任务节点右键 → "取消任务" 可还原为普通节点
- 已设置截止日期的任务取消时弹出确认："取消任务将同步删除截止日期和优先级，是否继续？"

#### 6.1.2 任务状态流转

```
[未开始] --点击复选框--> [已完成]
   ↑                        |
   └──── 再次点击复选框 ←──┘
```

- 点击复选框即时完成，无二次确认
- 已完成任务保留在原地（思维导图）或移入"已完成"列（看板），由用户设置决定
- 已完成任务显示删除线，整体色调 muted

### 6.2 视图切换动画（v1.1 更新为 5 视图）

五种视图之间切换时，保持一致的空间感知。

| 视图类型 | 标识 |
|---------|------|
| 思维导图 (Mind Map) | 项目级，显示思维导图画布 |
| 项目列表 (Project List) | 项目级，显示当前项目的任务列表 |
| 项目看板 (Project Kanban) | 项目级，显示当前项目的看板 |
| 全局任务列表 (Global List) | 全局级，聚合所有项目的任务列表 |
| 全局看板 (Global Kanban) | 全局级，聚合所有项目的看板 |

| 切换方向 | 动画方式 |
|---------|---------|
| 思维导图 ↔ 项目列表/看板 | 淡入淡出 (opacity 0→1)，持续 200ms |
| 思维导图 ↔ 全局视图 | 淡入淡出 + 轻微缩放 (scale 0.98 → 1.00)，给用户"空间层级切换"感知 |
| 列表 ↔ 看板（同级） | 滑动过渡：当前视图左滑退出 / 右滑进入，持续 250ms |
| 项目级 ↔ 全局级 | 深度切换：当前视图 scale(1) → scale(0.98) + opacity 0，新视图 reverse，持续 300ms |

**实现要求**：
- 所有动画使用 `transform` 和 `opacity`，不触发 reflow/repaint
- 支持 `prefers-reduced-motion: reduce` — 禁用所有过渡，切换为即时跳转
- 动画期间保持滚动位置记忆，返回时恢复
- **视图状态保持**：每个项目独立记忆用户最后选择的视图（思维导图/列表/看板），切换项目后恢复该项目上次的视图状态

### 6.3 拖拽交互

#### 6.3.1 思维导图内拖拽（调整层级/顺序）

| 场景 | 反馈 |
|------|------|
| 拖拽节点 | 节点 `opacity: 0.5`，原位置显示 ghost 占位框（虚线边框） |
| 悬停到另一节点 | 目标节点高亮（`--color-primary-subtle` 背景），显示将成为子节点的预览 |
| 悬停到节点之间 | 显示 `2px dashed --color-primary` 插入线 |
| 释放 | 节点飞入新位置，持续 200ms 弹性缓动 |

#### 6.3.2 看板拖拽（跨列移动）

| 场景 | 反馈 |
|------|------|
| 拖拽卡片 | 卡片缩小至 `scale(0.95)`，`opacity: 0.9`，原位置占位 |
| 悬停到列上方 | 列头高亮，列内显示插入位置指示线 |
| 跨列释放 | 卡片飞入目标列顶部/指定位置，任务状态自动更新为对应列状态 |
| 状态变化反馈 | 卡片边框闪烁对应优先级颜色（300ms），提示状态已变更 |
| **全局看板跨项目拖拽**（v1.1 新增） | 拖拽不改变项目归属，仅改变状态。释放时显示 toast："状态已更新" |

#### 6.3.3 列表拖拽（排序）

- 拖拽行时，其他行自动让出空间
- 插入位置显示 `2px solid --color-primary` 横线
- 释放后列表平滑重排（FLIP 动画，200ms）

#### 6.3.4 Sidebar 项目列表拖拽排序（v1.1 新增）

- 拖拽项目条目调整 Sidebar 中的项目排序
- 拖拽时项目 `opacity: 0.5`，原位置显示虚线占位
- 释放后列表重排，排序结果持久化到本地存储

### 6.4 项目操作流程（v1.1 新增）

#### 6.4.1 新建项目

**触发方式**：
1. Sidebar 项目区底部 "+ 新建项目" 按钮
2. 快捷键 `Cmd/Ctrl + Shift + N`
3. 首次进入空状态下的 CTA 按钮

**流程**：
- 弹窗打开（见 5.7 新建项目弹窗规格）
- 项目名称必填，自动聚焦输入框
- 项目颜色默认按顺序分配（新项目默认取 6 色池中下一个未使用颜色，全部使用后循环）
- 结构默认选择"逻辑图"
- 点击"创建"后：
  - 弹窗关闭（fade out 150ms）
  - Sidebar 项目列表顶部插入新项目（slide in from top 200ms）
  - 主画布切换至新项目的思维导图空状态
  - 画布显示 "按 Enter 创建第一个节点" 引导

#### 6.4.2 项目切换

- 点击 Sidebar 项目列表中的项目
- 主内容区按 6.2 的"项目级 ↔ 项目级"动画过渡
- 切换后恢复该项目上次使用的视图状态（思维导图/列表/看板）
- Header 中间指示器更新为当前项目名称
- 若当前在全局视图，点击项目后切换至该项目的思维导图视图

#### 6.4.3 项目重命名

- 右键/长按项目 → "重命名"
- 项目名变为 inline input，`text-sm`，高度 32px，全宽
- 原名称作为 input value 全选中
- Enter 确认，Esc 取消，失去焦点自动保存
- 保存时显示 inline saving spinner（Lucide `Loader2` 12px，旋转动画）
- 保存成功无提示，保存失败 input 边框变 `--color-danger`

#### 6.4.4 项目删除

- 右键/长按项目 → "删除项目"
- 二次确认弹窗（见 5.3.5）
- 确认后：
  - 弹窗关闭
  - Sidebar 中该项目 fade out（opacity → 0，150ms）
  - 若删除的是当前项目，自动切换到列表中的第一个其他项目；若无可切换项目，显示首次进入空状态

## 9. 附录：竞品 UI 分析摘要

### 9.1 Xmind 分析

- **节点风格**：根节点用色块填充（通常深色背景+白色文字），二级节点白底+彩色细边框，三级+节点纯文本。层级通过填充 vs 边框 vs 纯文本三级递减表达。
- **配色机制**：6 色配色方案，每开启一条新分支自动分配下一个颜色。颜色自动应用于连线、二级节点边框、概要。
- **交互亮点**：Command/Control + Enter 快速同级节点，Tab 快速子节点，空格展开/折叠。节点 drag 到另一节点上可改变父子关系。
- **可借鉴**：分支异色系统、层级递减权重、空格展开折叠。
- **需规避**：默认主题的多彩饱和度偏高（MindFlow 使用更克制低饱和的分支色）。

### 9.2 滴答清单分析

- **任务卡片**：单列表视图，每行 56px，左侧复选框，标题 + 右侧元数据行（日期/标签/优先级/清单名）。
- **优先级标识**：红点/橙点/蓝点，无文字，纯图标式。完成态变灰色删除线。
- **看板视图**：固定 4 列（箱式），列宽固定，卡片垂直堆叠，支持跨列拖拽。
- **全局列表**：滴答清单有"所有任务"聚合列表，可按清单（项目）筛选。
- **交互亮点**：左右滑动快速修改日期（移动端），智能识别日期文本。
- **可借鉴**：信息密度排列方式、复选框状态反馈、完成态视觉降级、全局任务聚合模式。
- **需规避**：界面信息密度在某些场景下不够紧凑；UI 风格偏工具化，美感不足；全局视图的项目筛选弱。

### 9.3 Notion 分析

- **侧边栏**：左侧宽栏，树状结构组织页面，支持嵌套、折叠、拖拽重排。hover 显示操作图标。
- **页面切换**：侧边栏点击即时切换，顶部面包屑显示当前页面路径。
- **视觉风格**：无多余 chrome，边框极少，依靠留白和字号建立层级。
- **可借鉴**：侧边栏信息架构、页面组织方式、极简边框策略、Sidebar Section 分区逻辑。
- **需规避**：初次加载偏慢；侧边栏层级过深时容易迷失。

### 9.4 Linear 分析

- **全局框架**：倒 L 形（侧边栏 + 顶部 Header + 主内容区），最大化内容空间。
- **主题系统**：极简 Token（从 98 个变量精简到 3 个核心变量 + LCH 色彩空间），强调对比度与一致性。
- **交互精度**：所有 hover/active 状态在 150ms 内完成，无迟滞感。按钮涟漪效果极简。列表行 hover 显示操作。
- **可借鉴**：全局框架结构、主题 token 精简哲学、交互响应速度、列表行操作模式、Sidebar 工作区/系统区的分区逻辑。
- **需规避**：Linear 纯 issue tracking，信息形态单一；MindFlow 需要融合思维导图的自由形态与任务的表格形态，不能直接照搬。
