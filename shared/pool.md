# MindFlow 共享内存池

## 竞品关键信息池（由 PM 维护，architect/designer 可直接引用）

### 直接竞品

#### Xmind
- **定位**：思维导图标杆工具
- **技术栈**：Electron 桌面应用 + 网页版
- **核心功能**：30+ 模板、10+ 结构组合、导出 10+ 格式（PNG/SVG/PDF/Markdown/Office）、演说模式、ZEN 模式
- **任务管理能力**：2025 年 Pro+ 才加入基础任务字段（优先级/分工/进度/时间），无看板/日历/提醒
- **定价**：免费版 ¥0（10 张导图限制）、Pro ¥380/年、Pro+ ¥420/年
- **关键差评**：免费版过度限制（仅10张）；本地存储为主云端弱；任务功能是"后加的"不够自然；移动端体验差
- **对 MindFlow 的启示**：不要后加任务功能——任务必须是核心实体；免费版要给足够用量建立依赖；必须做好云同步

#### 滴答清单 (TickTick)
- **定位**：任务管理标杆
- **技术栈**：跨平台原生应用 + 网页版
- **核心功能**：自然语言识别、日历多视图（年/月/周/日）、番茄钟、习惯打卡、农历循环、智能清单
- **思维导图能力**：无。纯列表/日历/看板视图，无层级可视化
- **定价**：免费版受限、付费版 ¥139-168/年
- **关键差评**：设计品味差（V2EX 热帖 2600+ 浏览）；UI 不统一（圆角/颜色/主题不一致）；免费版月/周视图需付费
- **对 MindFlow 的启示**：设计品质必须高过滴答清单（门槛很低但要做到）；核心视图不能付费墙；必须用思维导图解决复杂项目的层级可视化

#### GitMind
- **定位**：在线协作思维导图
- **技术栈**：Web 应用
- **核心功能**：AI 生成脑图、文档转脑图、多端同步、协作编辑、模板库
- **任务管理能力**：无内置任务系统
- **定价**：年费约为 Xmind 的 1/6，性价比路线
- **关键差评**：无外框功能；电脑版与手机版功能差异；协作稳定性一般
- **对 MindFlow 的启示**：网页技术栈可行（我们选 wanglin2/mind-map 类似）；AI 功能是加分项但不是 MVP；多端一致性要做好

#### 幕布
- **定位**：大纲笔记 + 思维导图
- **技术栈**：Web + 客户端
- **核心功能**：大纲编辑、一键转思维导图、多设备同步、Markdown 支持
- **任务管理能力**：有简单任务标记，但无提醒/看板/追踪
- **定价**：基础功能免费
- **关键差评**：样式选择极少；仅导出图片/PDF；功能薄弱；停止更新后由 Flomo 团队接手，前景不明
- **对 MindFlow 的启示**：大纲+导图的切换逻辑值得借鉴；但幕布证明了"太简单"活不下去，必须有任务闭环

### 间接竞品 / 替代方案

#### Notion
- **定位**：All-in-one 工作空间（笔记+数据库+任务+协作）
- **核心功能**：块编辑器、数据库视图（表/看板/日历/时间线/画廊）、模板生态、协作
- **思维导图能力**：无原生思维导图，需用第三方嵌入或手动画
- **定价**：免费版 Block 受限、Plus $8/月、Business $15/月
- **关键差评**：上手门槛极高；内容多了严重卡顿；全局搜索体验差；中文支持弱；离线访问差
- **对 MindFlow 的启示**：不要做 All-in-one——专注在"思维导图+任务"这个切口；性能必须好；保证离线可用

#### Obsidian
- **定位**：本地优先的知识管理
- **核心功能**：Markdown、双向链接、Canvas 可视化、插件生态（3000+）
- **思维导图能力**：Canvas 可手动摆放卡片模拟导图，有 Canvas Mindmap 插件但不专业
- **定价**：免费（同步服务 $4/月）
- **关键差评**：上手门槛极高；需要大量插件配置；移动端体验差；普通用户望而却步
- **对 MindFlow 的启示**：不要要求用户配置——开箱即用；但"本地优先+可选同步"的策略值得参考

#### Miro
- **定位**：协作白板（在线白板+思维导图+敏捷工具）
- **核心功能**：无限画布、实时协作、模板库、集成 Jira/Slack、AI 辅助
- **任务管理能力**：看板/时间线有，但非核心
- **定价**：免费版 3 个 board、Starter $8/月、Business $16/月
- **关键差评**：对个人项目过于复杂；大画布性能延迟；中国访问慢；贵
- **对 MindFlow 的启示**：个人用户不需要无限画布——控制在"项目管理"尺度即可；中国用户需要本地优化

## 设计方向池（由设计师维护）

#### 对标品牌与语言
- **全局框架 / 主题系统**：对标 Linear — 倒 L 形框架、极简 Token 体系、深色优先的主题
- **侧边栏 / 页面组织**：对标 Notion — 可折叠树状侧边栏、页面切换
- **节点样式 / 分支配色**：对标 Xmind — 层级递减视觉权重、分支异色、清晰连线
- **任务信息密度 / 完成态**：对标 滴答清单 — 复选框状态反馈、优先级标识、高效密度

#### 设计语言关键词
克制 · 层级 · 精准 · 沉浸 · 清晰

#### 配色基调
- **品牌主色**：Indigo `#4F46E5`（专业 SaaS 蓝紫，视觉上归入蓝色系，不作渐变主视觉）
- **背景体系**：浅色 `#F8FAFC` / 深色 `#0B0F19`（偏蓝黑，非纯黑）
- **任务优先级色**：高 `#EF4444`（红）/ 中 `#F59E0B`（橙）/ 低 `#3B82F6`（蓝）
- **思维导图分支色（6 色）**：Indigo / Teal / Amber / Rose / Emerald / Violet（低饱和，仅节点/连线级别，非 UI 渐变）
- **灰阶体系**：Slate 系列 `50-950`（`#F8FAFC` → `#020617`）

#### 字体方案
- **全局字体**：Inter + Noto Sans SC（PingFang SC fallback）
- **等宽字体**：JetBrains Mono（用于数值/时间戳）
- **字号层级**：11/12/13/14/15/16/18/20/24/32px（10 级，App 内最大 20px）

#### 布局核心
- **全局**：倒 L 形框架，Sidebar 默认 240px（可拖拽折叠），Header 48px
- **视图**：思维导图（无限画布，贝塞尔曲线连）/ 列表（Flex 行）/ 看板（280px 固定列宽）
- **视图切换**：Tab 胶囊 + 淡入淡出动画（200ms）

#### 节点设计关键决策
- **普通节点 → 任务节点**：border + 填充背景 + 左侧 3px 优先级竖条 + 复选框"实体化"效果
- **三级+普通节点**：`transparent` 背景 + 无边框 + 14px 次要文字，形成"弱信息"层级
- **根节点**：`--bg-surface` + 2px `--color-primary` 边框 + 16px 粗体，形成"强锚点"

#### 组件冻结清单
- 图标系统：Lucide（16/20/24px）— 已冻结
- 字体栈：Inter + Noto Sans SC + JetBrains Mono — 已冻结
- 间距网格：4px 基准 — 已冻结
- 圆角：4/8/12/16px 四级 — 已冻结
- 动效时长：最大 400ms，无弹跳缓动 — 已冻结

#### 反模式自查结论
- 无紫色渐变主视觉
- 无 Emoji 功能图标
- 无硬编码颜色值
- 无超大圆角
- 无弥散大阴影
- 无低对比度文字
- focus-visible / 键盘可达 / prefers-reduced-motion 全覆盖

- 完整 UIUX 设计文档：`/docs/UIUX.md`（含 10 章：设计方向、配色、字体、布局、组件规范、交互规范、Token 总表、反模式检查、竞品分析摘要、交付清单）

#### v1.1 新增设计方向（多项目 + 全局任务）

**核心定位升级**：从"单项目思维导图+任务"升级为"多项目工作台"——侧边栏成为项目的"停泊港"，全局任务成为跨项目作业的"指挥中心"。

**Sidebar 三区结构（新增冻结）**：
- **项目区**（顶部）：项目列表（项目色圆点 + 名称），底部 "+ 新建项目"，最大 20 个，hover 显示拖拽手柄+更多菜单，右键/长按可重命名/删除
- **全局区**（中部）："全局任务"入口，与项目区以分隔线区分，选中态同项目列表
- **系统区**（底部）：设置/帮助/快捷键/主题切换

**视图体系扩展**：
- 项目级（3 视图）：思维导图 / 项目列表 / 项目看板
- 全局级（2 视图）：全局任务列表 / 全局看板
- 视图状态保持：每个项目独立记忆最后使用的视图，切换项目后恢复

**项目颜色标识系统（新增冻结）**：
- 新建项目从 6 色池中按序分配（Indigo/Teal/Amber/Rose/Emerald/Violet），用户可修改
- 项目色用于：Sidebar 圆点 / 全局列表行标识 / 全局看板卡片顶部横条 / 项目标签胶囊
- **与优先级色的分离原则**：项目色在元素外缘（最左/顶部），优先级色在内侧（标题旁/左竖条），物理分离 ≥ 8px，形状不同（圆点 vs 竖条）

**全局任务列表行规格**：
- 行高 48px，包含：项目标识列（10px 圆点+缩写）/ 任务名称（flex-grow）/ 截止日期（100px）/ 优先级圆点（60px）/ 状态胶囊（80px）
- 支持 4 种分组模式：扁平列表 / 按项目分组 / 按截止日期分组 / 按优先级分组

**筛选栏规格**：
- 高度 48px，固定于全局视图的 View Header 下方
- 筛选 Chip 为胶囊形状（`radius-full`），激活态填充 `--color-primary-subtle`
- 项目筛选为多选下拉（带项目色圆点），优先级/状态为横向按钮组，截止日期为预设快捷+自定义范围

**空状态设计（新增）**：
- 无项目：居中插画 + "创建你的第一个项目" + CTA
- 项目画布无节点："按 Enter 创建第一个节点" 快捷键提示
- 看板无任务：每列中央 Lucide `BrainCircuit` 图标 + 引导文案
- 全局任务为空：`LayoutDashboard` 图标 + "还没有任务" + 指向 Sidebar 的视觉引导箭头

**新建项目弹窗**：
- 尺寸 420px，输入项目名称（必填≤50字）+ 6 色圆形选择器（默认按序分配）+ 结构选择（逻辑图/树形图/组织结构图）
- 2px 外圈选中态，`text-2xs` 颜色名称标签，回车确认

**交互更新**：
- 新建项目：`Cmd/Ctrl + Shift + N` / Sidebar 底部按钮 / 首次进入 CTA
- 快速切换项目：`Cmd/Ctrl + P`（Command 面板）
- 跳转全局：`G` → `L`（列表）/ `G` → `K`（看板）
- 项目切换动画：深度切换 scale(1)→scale(0.98)+opacity 0，300ms

**反模式自查 v1.1 新增项**：
- 项目色与优先级色无混淆风险（位置+形状双重区分）
- 全局视图无信息过载（筛选栏默认折叠，行高保持 48px，项目标签用缩写）

### 技术选型结论

| 领域 | 选型 | 版本 | 选型理由 |
|------|------|------|---------|
| 前端框架 | React + Vite | React 18, Vite 5 | 团队熟悉，与 mind-map 框架无关库兼容，shadcn/ui 生态 |
| 状态管理 | Zustand | 最新 | 轻量、TypeScript 友好、零模板代码 |
| UI 组件库 | shadcn/ui + Tailwind CSS | 最新 | 源码级控制、无运行时依赖、按需提供 |
| 思维导图库 | simple-mind-map (wanglin2) | 0.14.0-fix.2 | 国产开源、MIT 协议、框架无关、功能完备 |
| 本地存储 | IndexedDB (Dexie.js) | 最新 | 结构化存储、大容量（~50MB）、支持按项目分表 |
| 认证 | Supabase Auth | 内置 | 与数据库深度集成、免费、国内访问良好 |
| 数据库 | Supabase PostgreSQL | 14+ | 免费 500MB/5GB 出站、内置 Realtime |
| 实时同步 | Supabase Realtime | 内置 | Broadcast + Postgres Changes + Presence |
| 文件存储 | Supabase Storage | 内置 | 与 Auth 权限联动，免费 1GB |
| 部署 | Cloudflare Pages | 最新 | SPA 原生支持、国内 CDN 快、免费无限请求 |

### simple-mind-map 库关键约束

| 属性 | 说明 |
|------|------|
| **技术栈** | 纯 JavaScript，框架无关，基于 `@svgdotjs/svg.js` + SVG 渲染 |
| **体积** | 核心库轻量，插件按需加载 |
| **TypeScript** | 内置类型声明 |
| **维护状态** | 低维护（作者精力在闭源客户端版），但功能稳定 |
| **数据结构** | 递归树：每节点 `{ data: {...}, children: [...] }` |
| **自定义字段** | 需以 `_` 开头命名，如 `_isTask`、`_priority`、`_dueDate` |
| **React 集成** | 通过 ref + useEffect 初始化，事件 `data_change` 获取变更 |
| **导出** | PNG/SVG/PDF/XMind/Markdown/TXT/JSON/SMM（需注册对应插件） |
| **导入** | XMind/JSON/SMM（Markdown 需自行解析后 setData） |
| **大量节点** | 建议 <500 节点；开启 `openPerformance: true` 提升渲染 |

### 数据模型约束（v1.1 — `projects` 为顶层实体）

| 表 | 存储策略 | 外键 | 说明 |
|----|---------|------|------|
| `projects` | 项目元数据（名称、颜色、图标、排序、is_archived） | `user_id` → users.id | **多项目管理的顶层实体** |
| `mindmaps` | 1:1 关联 projects，完整 `tree_data` JSONB + `view_state` | `project_id` → projects.id（UNIQUE） | 每个项目对应一张思维导图 |
| `mindmap_nodes` | 扁平化节点数据 | `project_id` + `mindmap_id` | 独立查询、按层级排序、标识任务节点，冗余 project_id 优化跨项目统计 |
| `tasks` | 从节点提取的任务实体 | `project_id` + `mindmap_id` + `node_uid` | 支持项目看板 + 全局任务视图 + 跨项目筛选，冗余 project_id 优化全局查询 |
| `tags` | 用户级全局标签 | `user_id` | 项目标签 + 任务标签共用 |
| `project_tags` | 项目-标签关联（v1.1 替换 mindmap_tags） | `project_id` + `tag_id` | 以项目为维度打标签 |

**层级关系**：`users` 1:N `projects` 1:1 `mindmaps` 1:N `mindmap_nodes` ∥ `tasks`

**数据隔离**：
- 用户级：Supabase RLS `auth.uid() = user_id`
- 项目级：所有表含 `project_id`，查询自带 `eq('project_id', pid)`
- 客户端：Zustand `activeProjectId` 控制，组件按此筛选

**双写策略**：操作思维导图 → 触发 `data_change` → 异步遍历 tree 提取 `is_task=true` 的节点 → 按 `project_id` upsert tasks 表 → 更新 `globalTasks` 缓存。

### 全局任务查询路径（v1.1 新增）

| 查询场景 | 路径 | 索引支撑 |
|---------|------|---------|
| 全部任务（跨项目） | `tasks.user_id = uid` | `user_id + status + priority` |
| 按项目筛选 | + `project_id = pid` | `project_id + status` |
| 按优先级筛选 | + `priority IN [...]` | `user_id + priority` |
| 按状态筛选 | + `status = 'todo'` | `user_id + status` |
| 按截止日期（今日/本周/过期） | + `due_date` 范围查询 | `user_id + due_date` |
| 全局看板分组 | 先拉全部 → 前端按 `project_id` + `status` 分组 | `user_id + project_id + sort_order` |

**性能验证**：10 项目 × 100 任务 = 1000 行，`tasks` 表 `user_id` + `status` 复合索引下查询 <50ms。

### IndexedDB 本地存储架构（v1.1 新增）

| 存储表 | 数据内容 | 创建时机 | 清理时机 |
|-------|---------|---------|---------|
| `projects` | 项目元数据列表（id/name/color/icon/排序/归档状态） | App 启动时全量加载 | 项目删除时移除 |
| `mindflow_project_{id}`（动态表） | 该项目的完整节点树（扁平化存储） | 项目创建时动态注册 | 项目删除时 `dropTable` |
| `globalTasks` | 所有任务的聚合缓存（含 project_name/color） | 加载全局视图时写入 | 每次加载全局视图时全量刷新 |
| `globalViewState` | 全局视图的筛选条件、排序、列宽 | 切换筛选时写入 | 长期保留 |

**动态表注册**：Dexie.js `db.version().stores({ [tableName]: 'uid, ...' })`，项目删除时 `db.deleteTable(tableName)`。

### 实时同步策略（MVP）

| 方式 | 延迟 | 场景 | 冲突处理 |
|------|------|------|---------|
| **Broadcast（优先）** | <100ms | 同项目内多人/多设备实时协作 | 乐观更新 + `version` 序列号校验 |
| **Postgres Changes（兜底）** | 1-3s | 跨设备同步、离线恢复、数据持久化 | Last-Write-Wins |

**冲突处理规则**：
1. 版本号统一在 `projects` 表维护：`projects.version` 单调递增
2. 每次写入导图或任务时 `version += 1`
3. 客户端：若 `incoming_version <= local`，丢弃（已通过 Broadcast 收到）
4. 若 `incoming_version > local + 1`，触发全量重加载

### 性能红线（v1.1 更新）

| 约束项 | 阈值 | 优化手段 |
|--------|------|---------|
| 项目数量 | < 20 | 20个项目=20张IndexedDB动态表，性能可接受；超限归档旧项目 |

| 实时消息大小 | < 50KB | 图片走 Storage，广播只传节点 UID |
| 节点缓存 | < 500 | `maxNodeCacheCount: 500` |
| 内存占用 | < 200MB | 控制单页导图数量 + 全局任务缓存上限 |
| IndexedDB 存储 | < 40MB / ~80% quota | 超限提示导出清理，云端同步后缓解 |

### 已知技术风险（v1.1 更新）

| 风险 | 严重度 | 应对 |
