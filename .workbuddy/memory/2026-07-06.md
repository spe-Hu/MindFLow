## 迭代 31：修复严重 Bug — 云端同步数据丢失

## 迭代 32：修复云端数据库 uuid 类型与本地 string ID 不兼容

### 根因
本地项目/导图/任务 ID 使用自定义 string（如 `1783319987163-qivf9bl`，由 `Date.now() + '-' + random` 生成），但 `001_initial_schema.sql` 将所有业务表 `id` 列设为 `uuid PRIMARY KEY DEFAULT gen_random_uuid()`。PostgreSQL 在 upsert 时严格校验格式，直接将 string ID 塞入 `uuid` 列即报 `invalid input syntax for type uuid`，导致所有项目/导图/任务同步全部失败（共 33 项）。

### 方案
由于已有大量本地数据使用 string ID，不能改本地生成逻辑。改为将云端表的非 auth 列从 `uuid` 改为 `text` 类型。`user_id` 保持 `uuid`（外键指向 `auth.users.id`）。

### 改动
1. `supabase/migrations/001_initial_schema.sql`：
   - `projects.id` / `mindmaps.id` / `tasks.id` / `mindmap_nodes.id` / `tags.id` / `project_tags.id` / `task_tags.id`：`uuid` → `text`
   - 相关外键列（`project_id` / `mindmap_id` / `task_id` / `tag_id`）：`uuid` → `text`
   - `user_id` 保持 `uuid` 不变
2. 新增 `supabase/migrations/002_alter_uuid_to_text.sql`：
   - 用于已创建的云端表（用户的当前环境）
   - 步骤：循环删除所有外键约束 → ALTER COLUMN TYPE text → 重新添加外键约束
   - 云端数据安全（用户的 sync 此前全部失败，云端表大概率是空的或有极少量数据）
3. 前端代码无需改动（`sync.ts` 传递的 string ID 已正确，不需要额外 build/deploy）

### 执行步骤（需用户手动操作）
登录 Supabase 控制台 → SQL Editor → New query → 粘贴 `002_alter_uuid_to_text.sql` 全部内容 → Run。执行后测试「同步到云端」即可。
