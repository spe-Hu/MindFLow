Lesson 02 / 大模型训练全流程

Multi-Head Attention 与位置编码

单一视角只看到一种关系，真正理解一句话需要"多头并进"。但还有一个前提：模型得知道"谁在谁前面"。

上节课回顾

Self-Attention 让每个词同时看向整句话，用 Q/K/V 算出谁该关注谁。但它有两个尚未解决的硬伤：（1）一个头只能捕捉一种关系类型；（2）模型完全不认识"句子顺序"——你把词打乱，它看不出区别。

1. 为什么一个头不够用？

回到这个例子：

"猫坐在垫子上，因为它很温暖。"

当模型读到"它"时，Self-Attention 会帮它找到"垫子"（指代关系）。但注意——这句话还隐藏了1 "坐在"是一个动宾搭配，不是指代关系。一个 Query只能捕获一种模式，这就是为什么需要多头。至少两层需要被同时理解：

  • 指代关系：「它」→「垫子」
  • 动宾搭配：「坐」→「垫子」
  • 因果逻辑：「温暖」→「坐」的原因

如果只有一个头，模型会做什么？它只能选择2 在 softmax 的约束下，注意力权重总和为1。意味着加强一个关系必然削弱另一个。其中一种关系来分配注意力。分配权重时，强化了指代关系就会削弱动宾关系——这是零和博弈。

Multi-Head Attention 的解法：把参数空间切成好几份，每个"头"独立算自己的 Q/K/V，各自捕捉不同类型的关系：

论文原文用了 8 个头，现代 LLM 通常用 8、12、16 甚至 32 个头。3 GPT-3 用了 96 个头。注意头太多了不一定更好——每个头的维度 d_k = d_model / num_heads。头越多，每个头能"看到"的维度就越少，可能丢失细粒度特征。关键是：所有头并行计算，然后拼接（Concatenate），最后乘一个投影矩阵统一回原始维度。

2. 多头注意力的计算

把原始的 Q/K/V 投影到 h 个不同的子空间，每个子空间独立做 attention：

head_i = Attention(Q·W_i^Q,  K·W_i^K,  V·W_i^V)

MultiHead(Q,K,V) = Concat(head_1, ..., head_h) · W^O

其中投影矩阵的形状：

矩阵形状作用
WiQ[d_model, d_k]第 i 个头的 Query 投影
WiK[d_model, d_k]第 i 个头的 Key 投影
WiV[d_model, d_v]第 i 个头的 Value 投影
WO[h·d_v, d_model]拼接后的输出投影

实践里的约束简洁漂亮：d_k = d_v = d_model / h。比如 GPT-3 的 d_model=12288，h=96，那每个头的维度就是4 这解释了为什么"头多了不一定更好"——每个头在 128 维的小空间里工作，能学会的关系模式受到容量限制。128。

PyTorch 实现（不到20行核心）

import torch
import torch.nn as nn
import math

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, num_heads=8):
        super().__init__()
        assert d_model % num_heads == 0
        self.d_model = d_model
        self.num_heads = num_heads
        self.d_k = d_model // num_heads   # 每个头的维度
        
        # Q/K/V/O 的线性投影
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)
    
    def forward(self, x, mask=None):
        batch, seq_len, _ = x.shape
        h = self.num_heads
        
        # (1) 线性投影 + 按头拆分
        Q = self.W_q(x).view(batch, seq_len, h, self.d_k).transpose(1, 2)
        K = self.W_k(x).view(batch, seq_len, h, self.d_k).transpose(1, 2)
        V = self.W_v(x).view(batch, seq_len, h, self.d_k).transpose(1, 2)
        # 现在形状: [batch, h, seq, d_k]
        
        # (2) 每个头独立算 Scaled Dot-Product Attention
        scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.d_k)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float('-inf'))
        attn = torch.softmax(scores, dim=-1)
        out = torch.matmul(attn, V)  # [batch, h, seq, d_k]
        
        # (3) 拼接所有头，投影回 d_model
        out = out.transpose(1, 2).contiguous().view(batch, seq_len, self.d_model)
        return self.W_o(out)

# 试一下
x = torch.randn(2, 10, 512)  # batch=2, seq=10, dim=512
mha = MultiHeadAttention(d_model=512, num_heads=8)
print(mha(x).shape)  # [2, 10, 512] —— 和输入一样长，方便堆叠层

看懂上面三个步骤的 .view() + .transpose() 操作，你就搞懂了 Multi-Head 最微妙的部分：怎样把一个大向量切成多份，并行计算，再拼回来。

3. Transformer 的大漏洞：顺序盲

现在有一个关键问题。Self-Attention 的计算方式，是完全5 "置换不变性"（permutation invariance）在某些任务里是优势（如集合预测），但在序列建模里是致命缺陷。因为语言的意义高度依赖词序。位置无关的——你把句子里的词全部打乱顺序，Attention 矩阵只是行和列跟着重新排列，计算结果本身没有任何变化。

试试这个思想实验：

A: "猫追老鼠"
B: "老鼠追猫"

对 Transformer 来说，这两句子的 Self-Attention 矩阵在数学上几乎6 严格来说不是完全相同，因为 embedding 层每个词有唯一的向量。但错序后的"老鼠追猫"会被当作一个全新的、与"猫追老鼠"毫无关系的组合来处理——模型不知道它们共享相同的词，只是顺序不同。相同，只是矩阵的行/列对调了。模型不知道 A 和 B 是完全相反的意思。

核心洞察

Self-Attention 只能告诉你哪些词在相互作用，但不能告诉你谁在谁前面。词序是语言意义的核心载体——必须额外告诉模型。

4. 位置编码：给每个座位贴编号

4.1 原始方案：正弦/余弦位置编码

最简单的做法是给每个位置生成一个唯一向量，然后加到词向量上。原始 Transformer 论文用的是7 选正弦函数而不是学出来的向量，有两个好处：（1）可以外推到训练时没见过的更长序列；（2）相对位置关系（pos+k 与 pos 的差）可以通过线性变换推导出来。正弦波：

PE(pos, 2i)   = sin(pos / 10000^(2i / d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i / d_model))

每个位置 pos 得到一个 d_model 维的向量。不同频率的正弦波让这些位置向量既独特又有规律——相邻位置相似，远离位置差异大。

4.2 现代方案：RoPE（旋转位置编码）

正弦编码有一个问题：位置信息与语义信息的融合是加法，模型不容易从向量中拆分出"哪部分代表含义，哪部分代表位置"。

现代的 GPT、LLaMA、Qwen 等大模型改成了8 RoPE 来自 Su et al. (2021) 论文 RoFormer: Enhanced Transformer with Rotary Position Embedding。它的核心思想是把位置信息嵌入到注意力计算中，而不是提前加到词向量上。RoPE（Rotary Position Embedding），思路更优雅：

不是给向量"加上"位置信息，而是从几何角度，把词的向量旋转一个角度。位置越远，旋转角度越大。这样，两个词之间的相对位置直接由它们旋转后的内积决定——不需要额外存储位置向量。

两种位置编码的对比
方案原论文/代表模型方式优势缺点
正弦编码Attention Is All You Need (2017)加法：词嵌入 + 位置向量外推性强、无需学习位置与语义混合
绝对位置嵌入BERT / GPT-2学出来的位置向量更灵活长度受限、不能外推
RoPELLaMA / GPT-4 / Qwen旋转：注意力计算中夹角天然编码相对位置、外推性好略复杂
ALiBiBLOOM / MPT在 attention score 上加线性偏置超长文本友好有损位置精度

你不需要现在就搞懂 RoPE 的数学细节，只需要记住一句话：

"位置编码的存在，是因为 Self-Attention 本身不知道'谁在谁之前'。
RoPE 之所以取代正弦编码，是因为它让'相对距离'变成了可计算的东西。"

5. 一个完整的 Transformer Block 长什么样？

现在我们有了全部原料，一个标准的 Transformer layer（以 GPT 的 Decoder-Only 为例）看起来是这样的：

输入 x ───────────────────────────────────────┐
       │                                         │
       ▼                                         │
  [LayerNorm] ──→ MultiHeadAttention ──→ 残差连接 ─┤
       │                    │                    │
       │                    ▼                    │
       │              输出 z                     │
       │                                         │
       ▼                                         │
  [LayerNorm] ──→ FeedForward(MLP) ──→ 残差连接 ─┘
       │
       ▼
  输出到下一层

每个 block 有三件重要的事情发生：

  • Self-Attention："我去看整句话"
  • 残差连接 + LayerNorm：让梯度能穿越深层，训练稳定9 为什么 LayerNorm 放在前面（Pre-LN）而不是后面（Post-LN）？GPT-2 以后发现 Pre-LN 更稳定——先做归一化再计算，防止前期层输出爆炸。
  • Feed-Forward（MLP）：每个位置独立地做"思考"——两个大矩阵夹着非线性激活。FFN 存储了模型大部分的事实知识。

这些 block 被堆叠几十层（GPT-3 是 96 层），这就是"深度"的来源——不是一次理解整句话，而是逐层提炼。

把第1课和第2课拼在一起，你现在理解了 Transformer 的核心骨架：
